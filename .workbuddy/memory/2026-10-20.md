## 环境坑（本机 git 相关，务必记住）
- **`.git` 目录曾莫名整个消失过一次**：当时处在 merge 中途（commit ccd9cb6 之后），报错 "stash failed" 连带 "not a git repository"。所有工作源文件经核验完好，于是重建仓库重新提交（1ae834a）。`git -C <绝对路径>` 全程可用。
- **`refs/remotes/` 写入不持久**：`git fetch` 会打印 "[new branch] main -> origin/main"，但 `show-ref` 里没有、`refs/remotes/` 目录是空的、`status -sb` 显示 "origin/main [gone]"。→ 不要依赖本地 remote-tracking ref，要核验服务端就用 `git ls-remote` 或 clone 取证。
- **绕坑办法**：把远端拉到明确的本地分支 `git fetch origin main:refs/heads/rmt`，再 `git merge rmt --allow-unrelated-histories`，比 merge FETCH_HEAD 可靠（FETCH_HEAD 曾误报 "Already up to date"）。
- **诊断踩坑**：本机 coreutils 不全，`head`/`find`/`ls` 缺失 —— `git log | head` 会静默输出为空，容易被误判成"没有提交"。核验要用 python 或直接不用管道。
